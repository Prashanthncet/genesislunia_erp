# Deploying Genesis ERP live

Three pieces, each on the host that fits it best:

| Piece | Where | Why |
|---|---|---|
| Frontend (Next.js 15) | **Cloudflare Workers** (`genesis-erp-web`) | global CDN, free plan; built with OpenNext, not a static export |
| Backend (NestJS 11 + Prisma) | **Render** Docker web service (`genesis-erp-api`) | needs a long-running Node process, cron jobs and pg_dump |
| Database (PostgreSQL 17) | **Neon** (any managed Postgres works) | serverless PG, free tier, connection pooling |
| Uploaded files | **Cloudflare R2** (S3-compatible) | the API already ships an S3 driver; R2 is the free one |

The browser only ever talks to the Worker; `/api/*` is proxied to Render by
`next.config.ts`'s rewrite, so there is no CORS surface for normal use.

Nothing in this repo has been deployed yet — the steps below are the exact
runbook, and the data importer they use has been verified against a real
PostgreSQL 17 (all 49 tables, row-for-row).

## 0. What you need to create (once)

1. **Cloudflare → My Profile → API Tokens → Create token** with:
   `Workers Scripts: Edit`, `Workers R2 Storage: Edit`, `Account Settings: Read`.
2. **Render → Account Settings → API Keys → Create**.
3. **Neon → Create project** (Postgres 17, region Singapore/Frankfurt) and copy
   the **pooled** connection string. It looks like
   `postgresql://user:pass@ep-xxx-pooler.region.aws.neon.tech/neondb?sslmode=require`.
4. **Cloudflare R2 → Manage R2 API Tokens → Create** (Object Read & Write) for
   the bucket `genesis-erp-files`.

Never paste tokens or passwords into chat or commit them. Put them in the
dashboard (Render/Cloudflare) or in the git-ignored `backend/.env` locally.

## 1. Database: schema, then your data

```bash
cd backend
export DATABASE_URL="postgresql://…neon.tech/neondb?sslmode=require"

# schema (additive, idempotent)
npx prisma migrate deploy --schema prisma/postgres/schema.prisma

# your current dev data (SQLite → Postgres), verified 49/49 tables
DATABASE_URL="$DATABASE_URL" node scripts/sqlite-to-postgres-import.js

# dry run first if you like — prints the row counts without writing:
DATABASE_URL="$DATABASE_URL" node scripts/sqlite-to-postgres-import.js --dry-run
```

The importer copies every table that exists on both sides, coerces booleans
(SQLite stores 0/1), keeps timestamps in UTC (no IST shift), copies JSON and
password hashes unchanged, retries tables whose parents haven't landed yet, and
exits non-zero if any table ends with fewer rows than SQLite.

Fresh demo data instead of the copy: `npm run seed` (one login per role).

## 2. Backend on Render

```bash
export RENDER_API_KEY="rnd_…"
# create the service from the blueprint (repo root render.yaml, Docker, Postgres build)
render blueprint launch
```

Then fill the `sync: false` secrets in the Render dashboard:

| Key | Value |
|---|---|
| `DATABASE_URL` | the Neon pooled URL |
| `CORS_ORIGINS` | `https://genesis-erp-web.<account>.workers.dev` |
| `FRONTEND_URL` | same as above |
| `S3_BUCKET` / `S3_ENDPOINT` / `S3_ACCESS_KEY_ID` / `S3_SECRET_ACCESS_KEY` | R2 bucket + token (`S3_ENDPOINT=https://<account>.r2.cloudflarestorage.com`, region `auto`) |

`JWT_SECRET` is generated by Render. The image runs
`prisma migrate deploy --schema prisma/postgres/schema.prisma` and then
`node dist/src/main`; the health check is `/api/health`.

```bash
curl https://genesis-erp-api.onrender.com/api/health   # {"status":"ok",...}
```

Free plan note: the service sleeps after ~15 minutes idle, so the first request
takes ~40 s. Move to the cheapest paid instance for a demo you can't afford to
have cold.

## 3. Frontend on Cloudflare

```bash
cd frontend
export CLOUDFLARE_API_TOKEN="…"
export CLOUDFLARE_ACCOUNT_ID="…"
# BACKEND_URL is baked into the routes manifest at BUILD time
BACKEND_URL="https://genesis-erp-api.onrender.com" npm run cf:deploy
```

`npm run cf:build` produces `.open-next/worker.js` (verified locally: the
bundle is ~1.3 MB gzipped, under the Workers limit) and `npm run cf:preview`
runs it under workerd before you ship.

First deploy prints the URL, e.g.
`https://genesis-erp-web.<account>.workers.dev`. Point `CORS_ORIGINS` and
`FRONTEND_URL` at it and redeploy the API.

## 4. Smoke test in the live app

1. `https://genesis-erp-api.onrender.com/api/health` → ok.
2. Sign in on the Worker URL with an imported account (e.g. the school admin).
3. Students → open a profile → download a report card (proves PG + R2).
4. Attendance → mark a class and save (proves the tenant/transaction path).
5. Fees → open an invoice PDF.

## 5. Things that are still honest gaps

- **Payments**: add real `RAZORPAY_KEY_ID`/`RAZORPAY_KEY_SECRET`; without them the
  mock gateway is used (dev-only).
- **SMS / email**: set an SMTP or MSG91/Twilio provider; otherwise notifications
  are logged as `mocked`, which the UI shows truthfully.
- **Seed credentials** from `DEMO_LOGINS` are public in the repo — change those
  passwords in the live app before sharing the URL.
- **Backups**: Neon keeps point-in-time history on paid plans; enable
  `BACKUP_S3_BUCKET` (Render cron or `npm run backup`) for off-site dumps.
- **SQLite** is a dev convenience only; production must use Postgres.
